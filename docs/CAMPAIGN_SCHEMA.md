# Falcon Strike-AI — Campaign Plan Schema Specification

**Document Version:** 1.0.0  
**Date:** 2026-11-01  
**Project:** Falcon Strike-AI  
**Conformance:** PRD FR-2.1, FR-2.3, FR-2.6  

---

## 1. Overview

Campaign plans represent structured, multi-stage adversary emulation sequences generated by the Agentic Campaign Planner. Every plan is strictly validated against Pydantic schemas and bounded by the Safety Policy Gate before any dry-run or simulation can be executed.

---

## 2. Campaign Data Contract (`CampaignPlan`)

| Field Name | Type | Description | Invariant / Validation Rule |
| :--- | :--- | :--- | :--- |
| **`campaign_id`** | `str` | Unique campaign identifier (e.g., `CAMP-A1B2C3D4`). | Immutable UUIDv4 hex prefix. |
| **`schema_version`** | `str` | Version of the campaign schema (`1.0.0`). | SemVer format. |
| **`run_id`** | `str` | Correlation run ID threading audit logs. | Required; matches active execution run. |
| **`created_at`** | `str` | UTC ISO-8601 timestamp. | Generated at planning time. |
| **`source_attack_path_id`** | `str` | Reference to the ranked attack path grounded upon. | Must exist in active graph discovery. |
| **`objective`** | `str` | High-level emulation objective description. | Non-empty operational statement. |
| **`target_resources`** | `list[str]` | Unique resource IDs touched across all stages. | Maximum 5 resources per campaign. |
| **`stages`** | `list[CampaignStage]` | Ordered sequence of execution stages. | Minimum 1, Maximum 10 stages. |
| **`selected_techniques`** | `list[str]` | List of all technique IDs used in this plan. | Every ID must exist in Technique Registry. |
| **`expected_iocs`** | `list[str]` | Ground-truth benign IOC signatures emitted. | Aggregated from technique contracts. |
| **`expected_telemetry`** | `list[str]` | CloudTrail / VPC flow log signatures expected. | Aggregated from technique contracts. |
| **`risk_summary`** | `str` | Assessment of blast-radius & safety bounds. | Non-empty safety assurance. |
| **`planner_provider`** | `str` | Provider used: `deterministic`, `gemini`, `openai`. | Explicit provider attribution. |
| **`planning_rationale`** | `str` | Transparent justification of staging & targeting. | Explainable rationale. |
| **`approved_by_policy`**| `bool` | Whether plan has passed Safety Policy Gate. | Defaults to `False`. |

---

## 3. Stage Data Contract (`CampaignStage`)

| Field Name | Type | Description |
| :--- | :--- | :--- |
| **`stage_id`** | `str` | Unique stage identifier (e.g., `STAGE-9F2B1A`). |
| **`stage_name`** | `str` | Descriptive label for this operation. |
| **`tactic`** | `AttackTactic` | MITRE ATT&CK tactic (e.g., `Initial Access`, `Privilege Escalation`). |
| **`technique_id`** | `str` | Approved technique ID (e.g., `T1078`, `T1098`). |
| **`technique_name`** | `str` | Canonical technique name from registry. |
| **`target_resource_id`** | `str` | ARN or resource ID of the target. |
| **`action_parameters`** | `dict[str, Any]`| Safe, inert parameters passed to emulation module. |
| **`expected_observation`** | `str` | Security log or telemetry observable upon execution. |
| **`estimated_risk`** | `TechniqueRiskLevel` | Risk classification: `LOW`, `MEDIUM`, `HIGH`. |
| **`dependencies`** | `list[str]` | Prerequisite stage IDs that must succeed first. |

---

## 4. Blast-Radius Constraints (NFR-S5)

- **`MAX_CAMPAIGN_STAGES`**: 10 stages.
- **`MAX_TARGET_RESOURCES`**: 5 distinct resources.
- **`MAX_ACTIONS_PER_CAMPAIGN`**: 20 actions.
- **`MAX_DURATION_SECONDS`**: 300 seconds.
